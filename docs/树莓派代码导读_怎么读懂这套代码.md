# 树莓派代码导读：怎么把这一整套代码看懂

> 适用：`~/ros2_ws/src/` 下 16 个包、约 2.3 万行源码。
> 目标不是「读完全部」，而是**建立一张地图**，以后任何一个节点你都能在 10 分钟内说出它「吃什么、吐什么、什么时候吐」。

---

## §0 先破一个误会：这不是一坨代码，是一条流水线

你现在觉得是黑箱，是因为把它当成「一个程序」。实际上它是**五层流水线**，每层只跟相邻层说话：

```
第1层  传感器      雷达驱动、摄像头桥、小车蓝牙桥、飞控桥
第2层  定位        激光 SLAM（Cartographer）→ 坐标(TF) → 坐标提供者
第3层  控制        PID → 速度指令
第4层  执行        飞控（PX4）→ 电机
第5层  任务/通信   任务状态机、地面站、黑匣子
```

**读代码的顺序必须和第 0 层相反**：从上往下读会晕，从「消息长什么样」开始最省力。

---

## §1 读任何 ROS 2 包的固定四步法（这是可迁移的技能，比记住本项目更重要）

一个 ROS 2 包 90% 的信息集中在四个地方。以后看到任何陌生包，照这个顺序走：

### 第 1 步：`package.xml` —— 它依赖谁
```bash
cat src/<包名>/package.xml | grep -E "depend|name|version"
```
- `<buildtool_depend>ament_cmake</buildtool_depend>` ⇒ C++ 包
- `<buildtool_depend>ament_python</buildtool_depend>` ⇒ Python 包
- 看 `<depend>` 列表就知道它跟谁打交道（有 `tf2_ros` 说明用坐标变换，有 `serial` 说明开串口）

### 第 2 步：`CMakeLists.txt` —— 可执行文件到底叫什么
```bash
grep -n -E "add_executable|add_library|install\(TARGETS" src/<包名>/CMakeLists.txt
```
★ **`ros2 run` 用的是 `add_executable` 里的名字，不是目录名，也不是 .cpp 文件名。** 这是新手最容易卡住的地方（你已经踩过一次：`CMakelists.txt` 小写 l，colcon 直接当没这个包）。

### 第 3 步：`main()` 往上，找构造函数 —— 节点的「户口本」
```bash
grep -n -E "create_publisher|create_subscription|declare_parameter|create_wall_timer|create_timer" src/<包名>/src/*.cpp
```
这一条命令就能同时回答四个问题：

| 关键字 | 回答的问题 |
|---|---|
| `create_subscription` | 它**吃**什么（话题名 + 消息类型） |
| `create_publisher` | 它**吐**什么 |
| `declare_parameter` | 它的**旋钮**有哪些、默认值多少 |
| `create_wall_timer` | 它多久动一次手（控制频率） |

### 第 4 步：回调函数 —— 「什么时候吐」
```bash
grep -n -E "void .*\(.*msg|on_pose|on_scan|callback|publish_output|timer" src/<包名>/src/*.cpp
```
找到那个被 timer 或订阅调用的函数，从里面看它的**判断条件**（超时？无效？越界？）——**安全逻辑几乎全在这些 if 里**，也就是炸机风险的藏身处。

> 四步法记成一句话：**依赖 → 名字 → 户口本 → 触发器。**

## §2 先把「数据长什么样」搞清楚：`uav_interfaces`

`src/uav_interfaces/msg/` 只有 10 个 `.msg` 文件、共 126 行，但**整条流水线的词汇表都在这里**。先读它，后面所有代码都变成「谁往这个词里填数」。

| 消息 | 谁发 | 谁收 | 含义 |
|---|---|---|---|
| `Waypoint.msg` / `WaypointList.msg` | 任务层 | PID | 目标点（x, y, yaw） |
| `FlightCommand.msg` | 飞控桥 | 记录器/地面站 | 发给飞控的指令帧 |
| `FlightStatus.msg` | 飞控桥 | 任务层/地面站 | 飞控回报（是否解锁、高度有效、failsafe…） |
| `FlightDirective.msg` | 任务层 | 飞控桥 | 「起飞 / 降落 / 定点」这类高层命令 |
| `MissionStatus.msg` / `MissionSync.msg` | 任务状态机 | 其它 | 任务阶段、同步 |
| `UavStatus.msg` | 系统 | 地面站 | 整机汇总状态 |
| `CarStatus.msg` / `GcsStatus.msg` | 小车桥 / 地面站桥 | 各层 | 小车与地面站的回报 |

看一条就够：
```bash
ros2 interface show uav_interfaces/msg/FlightStatus
```
**验收标准**：你能不看文档说出 `FlightStatus` 里哪几个字段是「安全门」（提示：找 `valid`、`failsafe`、`armed` 之类的名字）。

## §3 全链路地图：从雷达到电机，每一跳落在哪个文件

这是你要在脑子里建的那张图。左边是数据，右边是代码位置。

```
① 雷达转动
   └─ lslidar_driver/src/lslidar_driver.cc  ~1140 行（驱动本体，只看一处）
      · :1188  scan->header.stamp = start_time;   ← 时间戳用「扫描开始时刻」，别改
      · :800-825 时钟跳变闩锁（相邻扫描间隔 >0.5 s 就永久停发 /scan，重启才恢复）
      产出话题：/scan  (sensor_msgs/LaserScan)

② SLAM
   └─ cartographer_config/   ← 0 行 C++，只有配置和 launch
      · configuration_files/n10_2d.lua   调参全在这里
      · launch/n10_cartographer.launch.py
      产出：TF 树 map → odom → base_link      ← ★ 注意：没有话题，只有坐标变换

③ 坐标提供者
   └─ map_coordinate_provider/src/map_coordinate_node.cpp（545 行，很好读）
      · :39-51   参数（map_frame / base_frame / 限幅）
      · :115     tf_buffer_->lookupTransform(map_frame_, base_frame_, ...)
      · :60-63   发布 /map/current_pose (PoseStamped) 与 /map/current_pose_valid (Bool)
      · :315     int main()
      产出：/map/current_pose

④ PID
   └─ position_pid_controller/src/position_pid_node.cpp（1708 行，结构最标准）
      · :34      class PositionPidNode : public rclcpp::Node
      · :40-95   一大片 declare_parameter（x/y/yaw 三轴各一套 kp/ki/kd/限幅）
      · :165-166 发布 /pid/cmd_vel (TwistStamped)
      · :656-667 publish_output()：linear.x/y = 速度，angular.z = 偏航角速度
                ★ header.frame_id 恒为 map_frame_ ⇒ 这是「地图系速度」，不是机体系
      产出：/pid/cmd_vel

⑤ 飞控桥（旧：自定义串口协议；即将换成 MAVLink）
   └─ flight_controller_bridge/src/flight_controller_bridge_node.cpp（3354 行，只需读 70 行）
      · :270-273 发布 /flight/command、/flight/status
      · :277-278 订阅 /pid/cmd_vel
      · :284-299 订阅 /pid/control_valid、/map/current_pose、/map/current_pose_valid
      · :305-337 订阅 /waypoint/current、/mission/status、/mission/land_request、/flight/directive
      · :370-392 全部参数与默认值（超时、限幅、安全门开关）
      产出：串口字节 → 飞控 → 电机
```

**关键认知**：第 ①②③ 层你几乎不用动（已验证能跑）；**第 ⑤ 层整个要换掉**；第 ④ 层的 PID 一行不用改。

## §4 七个包的阅读顺序（按「读了能立刻懂」排序）

不要按目录字母顺序读。按这个顺序，每个包最多花 30 分钟。

### ① 先读 `px4_test`（590 行，你自己参与写的，最小）
**为什么第一个读**：它是我们上周一起搭的，只有 4 个 `.cpp`，每个都不超过 200 行，能完整看明白「一个节点从启动到发消息」的全过程。

```bash
cat src/px4_test/src/px4_cmd_test.cpp
```
关注：`main()` 怎么建节点 → 构造函数里 declare_parameter → 创建 publisher/subscriber → `create_wall_timer` → 定时器回调里 `pub_->publish(msg)`。

**读懂这一份，其它包的骨架全一样。**

### ② `position_pid_controller`（1708 行）—— 结构最标准的一个
这是全项目写得最规整的 C++ 节点，适合当模板读。
```bash
grep -n -E "^class|^void|^int main|create_|declare_" src/position_pid_controller/src/position_pid_node.cpp
```
重点理解三件事：
1. **它为什么有 20 个 declare_parameter**：x/y/yaw 三轴各一套 PID 增益 + 限幅，`config/position_pid_params.yaml` 里给值
2. **`publish_output()` 在 :656-667**：把三个 PID 的输出拼成一条 TwistStamped
3. **`header.frame_id = map_frame_`**：这条速度是**地图系**的（ENU），将来换算成 PX4 的 NED 只需换 x/y、翻 z，不用管机体朝向

### ③ `map_coordinate_provider`（545 行）—— 学 TF 用法
TF 是 ROS 2 里最抽象的东西，这个包是它最小的用法示例。
```bash
sed -n '100,130p' src/map_coordinate_provider/src/map_coordinate_node.cpp
```
理解：**「查坐标」不是订阅话题，是问一个叫 `tf_buffer_` 的黑板**。`lookupTransform("odom", "base_link", 时刻)` = 「odom 坐标系里，base_link 在哪、朝哪」。

★ 项目里的一个隐藏约定：`config/coordinate_params.yaml` 里 `map_frame: "odom"`（不是 `map`），因为飞行用的是局部连续的 odom，`map` 帧只给建图显示。

### ④ `LSLIDAR_X_ROS2-20240228`（1140 行）—— 驱动，只看 2 处
不要通读驱动，驱动都一个样：读串口 → 拆包 → 拼成 LaserScan → publish。
```bash
grep -n "scan->header.stamp\|scan_clock_jump_latched_\|create_publisher" src/LSLIDAR_X_ROS2-20240228/src/lslidar_driver/src/lslidar_driver.cc
```
只看两处：**时间戳怎么给的**（:1188）、**什么情况会停止发数据**（:800-825）。这两处是踩过的坑。

### ⑤ `cartographer_config`（116 行，0 行 C++）—— 纯配置
它自己没有任何算法代码，只是把第三方 `cartographer_ros` 用参数装配起来。
```bash
cat src/cartographer_config/configuration_files/n10_2d.lua
```
**读完你会明白：SLAM 的质量几乎全由这一个 lua 决定**，而不是由代码决定。

### ⑥ `flight_controller_bridge`（3354 行）—— 只读接口，不读协议
**重要**：这一整个包即将被 MAVLink 版本取代。所以：
- ✅ 要读：`:270-340`（发布/订阅了什么）和 `:370-392`（参数清单）
- ❌ 不要读：`protocol.cpp`（自定义串口帧的打包解包，30 字节帧、CRC16、状态位……已经被淘汰）

**读它的唯一目的：知道「上层要的接口长什么样」，新节点照着这个接口实现，上层代码一行都不用改。**

### ⑦ 最后读 `waypoint_manager`（4720 行）—— 任务状态机
最大、最复杂，但它是**业务逻辑**，不影响飞行安全，可以最后读、也可以先跳过。
```bash
grep -n -E "enum class|switch \(|case " src/waypoint_manager/src/competition_mission_node.cpp | head -40
```
状态机代码的读法：先找到 `enum class State`，把所有状态列出来，然后找 `switch(state)`，看每个状态「什么条件下转到下一个状态」。**不用管细节，先把状态图画出来。**

## §5 工具箱：十条命令，覆盖 90% 的阅读需求

```bash
# ── 运行前 ──
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash        # 每个新终端都要 source 两次

# ── 看系统里现在跑着什么 ──
ros2 node list                             # 有哪些节点在跑
ros2 node info /节点名                      # 这个节点订阅/发布什么（★ 最有用的一条）
ros2 topic list                            # 有哪些话题
ros2 topic info -v /话题名                  # 类型 + 谁在发 + 谁在收 + QoS

# ── 看数据 ──
ros2 topic echo /话题名 --once              # 看一条长什么样
ros2 topic hz /话题名                       # 频率（Ctrl-C 退出）
ros2 interface show 包名/msg/消息名          # 消息定义

# ── 看坐标系 ──
ros2 run tf2_ros tf2_echo odom base_link   # 实时打印 odom→base_link
ros2 run tf2_tools view_frames             # 生成 TF 树图（PDF）

# ── 看参数 ──
ros2 param list /节点名
ros2 param get /节点名 参数名

# ── 改完代码要重新编译 ──
cd ~/ros2_ws && colcon build --packages-select 包名 --symlink-install
```

★ 三个必须记住的因果：
1. **`ros2 run` 找的是 `install/` 里编译过的，不是 `src/` 里的源码** ⇒ 改了代码不 `colcon build` 等于没改
2. **`install/` 是 `--symlink-install` 装的** ⇒ Python 文件与 `config/*.yaml` 改完立刻生效，C++ 必须重编译
3. **`ros2 topic hz` 显示 0 Hz 但话题存在** ⇒ 多半是没人真在发，或者跨机器 DDS 发现被网络干扰

## §6 三个练习（做完你就不觉得是黑箱了）

### 练习 1（15 分钟）：画出 `position_pid_controller` 的数据流
任务：不看本文档，自己找出它订阅了什么、发布了什么、有没有 timer、频率多少。

## §7 七个常见困惑速查

| 困惑 | 答案 |
|---|---|
| 参数在代码里还是在 yaml 里？ | **代码里只有默认值**（`declare_parameter("x_kp", 0.5)`），实际值在 `config/*.yaml`，由 launch 传进去。yaml 优先 |
| 我改了 yaml 为什么没生效？ | 用的不是 `--symlink-install`，或者改的不是 `install/` 里那份，或者节点压根没用那个 launch 起 |
| `src/` 里的包和 `install/` 里的包什么关系？ | `src/` 是源码，`colcon build` 后产物装到 `install/`；`ros2 run` 只认 `install/` |
| 为什么有两个 `odom`？ | 一个是 TF 里的坐标系名，一个是 Cartographer 发布的变换名，本项目里**没有 `/odom` 话题** |
| 代码里找不到 `NED`/`FRD` 是正常的吗？ | 正常。**旧工程全用 ENU + FLU**，PX4 的 NED/FRD 只在即将新写的节点里出现 |
| `csm` 和 `ros2_laser_scan_matcher` 是什么？ | 上游雷达套件带的扫描匹配库，**本项目已弃用**（和 Cartographer 抢 `odom`），不要恢复 |
| 为什么 launch 里节点要延迟 3 秒/6 秒起？ | 等上游先就绪：t=0 传感器、t=3 SLAM、t=6 坐标、t=7 PID、t=9 任务 |

## §8 下一步：新节点会插在哪

你要接入的 PX4/MAVLink 节点，位置是**替换掉第 ⑤ 层**：

```
现在：  /pid/cmd_vel ──► flight_controller_bridge ──► 自定义串口 ──► 凌霄飞控
以后：  /pid/cmd_vel ──► px4_mavlink_bridge   ──► MAVLink ──► PX4
```

只要新节点**照样订阅 `/pid/cmd_vel`、`/map/current_pose`、`/map/current_pose_valid`，照样发布 `/flight/status`**，那么 ①②③④ 层和任务层**一行都不用改**。

这就是为什么 §4⑥ 那 70 行（`:270-340`）是你现在最该读的代码——**它是新旧两代的接口契约。**
