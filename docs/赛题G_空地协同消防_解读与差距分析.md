## 一、题目到底要什么

### 1. 场景

四旋翼无人机 + 消防车，组成空地协同系统。无人机腹部固定一支**垂直向下的激光笔**，
用激光点在地面上画出巡逻航迹；发现火情后先做初步处置，并把火源坐标告诉消防车，
消防车开过去把火源熄灭。

### 2. 场地（图 1）

| 项 | 数值 |
|---|---|
| 巡防区尺寸 | **48dm × 40dm**（4.8 m × 4.0 m） |
| 坐标原点 | 左下角 (0, 0)；右上角 (48, 40)；**单位 dm** |
| 地面坐标线 | 1dm × 1dm，淡蓝色 R180/G230/B255 |
| 底色 | 淡灰 R240/G240/B240 |
| 街区 | **白色**，消防车不得驶入 |
| 街区数量 | 图中 6 个圆角矩形，其中 3 个有红星（火源位置） |
| 辅助定位 | 上方与右侧各一条 **1.8cm 宽黑线**；也可用 UWB，但锚点必须在巡防区及其上方空间之外 |
| 起降点 | 左下角**黑色**方块（7dm），消防车停车点在它右边**红色**方块（5dm） |
| 安全网 | 四周 + **顶部**都有；支架在网外 |

### 3. 基本要求（50 分）

| # | 要求 | 分 |
|---|---|---|
| 1 | 自制模拟火源：电池供电红色 LED，带 **60° 喇叭遮光罩**（高 ≤10cm、发光面 ≤2cm）；用激光笔持续照 **2 s 开、再 2 s 关** | 5 |
| 2 | 展示规划航线图；**车上按键一键启动**，无人机垂直起飞到 **18dm**，按规划航线完成全覆盖巡逻 | **22** |
| 3 | 无人机与消防车无线通信；巡逻期间**每秒 1 次**发位置坐标，车上实时显示 | 8 |
| 4 | 车上显示**巡逻航迹曲线**，计算并显示**累计巡航航程** | 8 |
| 5 | 巡逻完成后返回，**准确降落在起飞区域内** | 7 |

### 4. 发挥部分（50 分）

| # | 要求 | 分 |
|---|---|---|
| 1 | 评委用激光笔点亮一个火源 → 无人机巡逻中发现火情 → 前往接近（水平距离 **≤5dm**）确认 → 机上 **LED 示警** | 8 |
| 2 | 飞到火源**正上方**，降到 **10dm**，悬停 **3 s** 抛洒灭火包；落点在以火源为圆心**半径 3dm** 圆内；然后把火源坐标发给车 | **12** |
| 3 | 车收到坐标后出发，**途中不得碾压街区及其边界线**，在 **5dm** 内用激光笔照射熄灭 | **15** |
| 4 | 熄灭后车返回出发区域 | 10 |
| 5 | 其他 | 5 |

### 5. 硬性约束（扣分/禁用项）

- 无人机**轴距 ≤45cm**；**桨叶必须全防护**（否则不予测试）。
- 机上激光笔**垂直向下、固定不得移动转动**；地面光斑 **≤6mm**；车上激光笔光斑 **≤2cm**。
- **一键启动后全程不得人为干预**；启动/急停装置启动后必须立刻交给工作人员。
- 调试与测试必须戴防护眼镜、手套，穿长袖长裤。
- 消防车：4 轮电动小车，投影 **≤25cm × 35cm**，高 ≤40cm，**不得使用麦克纳姆轮**。
- 测试全程**不得换电池**（两次测试之间可换，限 2 分钟）。
- 每次测试**限时**：发挥部分须在 **360 s** 内完成。
- 现场光照不可控（顶部照明、窗外光），**不得提出光照条件要求**。

### 6. 「覆盖」怎么判

判覆盖的单位是 **8dm × 8dm 粗线框**。无人机巡逻时激光笔扫到某个粗线框内**任意一点**，
即视为该区域被覆盖。48/8 = 6 列，40/8 = 5 行 ⇒ **共 30 个格子要全部扫到**。

## 二、把这题翻译成我们的技术指标

| 题目要求 | 我们的技术指标 | 现有能力 |
|---|---|---|
| 18dm 高度定高巡航 | 绝对高度 ±10cm 级 | ✅ 光流 + 测距 + EKF2，已实测 |
| 按航线全覆盖 | 水平定位精度 ~10cm，航点跟踪 | ⚠️ 雷达 SLAM，实测漂移量级可接受但有微小偏移 |
| 一键启动全自动 | offboard 全程 + 任务状态机 | ❌ 待写（`px4_offboard` + `competition_g`） |
| 每秒 1 次坐标上报 | TCP 1 Hz | ❌ 待写（`car_link`） |
| 发现火源 | 下视相机红点检测 | ❌ 队友在 K230 上做 |
| 飞到火源正上方 | 视觉伺服 | ❌ 队友在 K230 上做，我们接数据 |
| 抛洒灭火包 | 舵机/电磁铁 + 投放机构 | ❌ 待定 |
| 准确降落 | 降落精度 ±15cm | ⚠️ Position 模式已能稳定悬停与落地 |

### 关键认知：这题的分数分布

- **22 分只考「按规划航线全覆盖」** —— 这是纯定位+控制题，正好是现有 SLAM + PID 的强项。
- 视觉相关的两部分（发挥①②）共 20 分，**全部由 K230 承担**，树莓派只接结论。
- 小车有关的两部分（发挥③④）共 25 分，**由队友负责车辆本身**，我们只需把坐标发准。

⇒ **我们的主战场是「定位 + 航线跟踪 + 任务调度 + 通信」，不是视觉。**

## 三、航线设计

### 蛇形（boustrophedon）扫描

取 **y = 4, 12, 20, 28, 36 dm** 五条横线 —— 每条都穿过对应那一行 8dm 格子的中线：

```
(0,4) → (48,4) → (48,12) → (0,12) → (0,20) → (48,20) → (48,28) → (0,28) → (0,36) → (48,36)
```

| 指标 | 值 |
|---|---|
| 总航程 | 5 × 48 + 4 × 8 = **272 dm = 27.2 m** |
| 0.6 m/s | 约 55 s |
| 0.8 m/s | 约 44 s |
| 1.0 m/s | 约 37 s |
| 纵向容差 | **±4dm（±40cm）** —— 非常宽 |
| 横向容差 | 每个格子 8dm 宽，扫到任一点即可 ⇒ 也极宽 |

★ 结论：**航线容差极其宽松**，±40cm 的定位误差都还能全覆盖。
这解释了为什么「建图有微小偏移但实测可用」并不致命 —— 关键在于**不要累积漂移到超过 40cm**。

### 时间预算（360 s 上限）

| 阶段 | 估算 |
|---|---|
| 起飞到 18dm | 5 s |
| 蛇形巡逻 | 44–55 s |
| 3 次火情处置 | 3 × ~16 s = 48 s |
| 返航 + 降落 | 20 s |
| **合计** | **约 130 s** |

⇒ 时间余量充足。真正的风险不是超时，而是**某一步卡住**（例如视觉对准失败、投放未触发）。

## 四、四个必须现场验证的风险

| # | 风险 | 为什么危险 | 怎么验 |
|---|---|---|---|
| **R1** | **安全网对 2D 雷达是否透明** | 整片场地的 SLAM 依赖四周几何约束。如果安全网反射激光，雷达会看到「一层墙」，地图会退化甚至把人挡在外面；如果完全穿透，空地边界就没了约束 | 到场先把雷达架起来看 `/scan`。若被挡住，考虑把雷达装高一点从网眼中穿出去，或改用场地内的白色街区棱边做特征 |
| **R2** | **SLAM 坐标系与场地坐标系的一次性对齐** | 所有航点都以「左下角为原点的 dm 坐标」表达，而 SLAM 的 `odom` 原点在开机位置、朝向随机。**必须做一次标定把两者对齐**，否则整条航线整体旋转/平移 | 在起降点放飞机，开机建图，把飞机手动推到两个已知场地点（如 (0,0) 与 (48,0)），记录 `odom` 读数，算出旋转+平移 |
| **R3** | **60° 遮光罩只在正上方可见** | 火源发光面被限制在 60° 锥内。下视相机必须几乎正对才能看见；斜着看会被罩子挡死 | 换算：相机 FOV 60°、高度 1.8m 时视场约 21dm，扫描线间距 8dm ⇒ 覆盖够，但**必须飞在火源上方附近才能看见** |
| **R4** | **投放是自由落体** | 1.0m 高自由落体 0.45 s；若此时水平速度 0.2 m/s，落点偏 9cm —— 远小于 30cm 容差。**真风险是坐标算错，不是物理漂移** | 悬停 3 s 期间要确认位置稳定在 ±5cm 内再投 |

```
                                       │                            │
                                       ▼                            ▼ /pid/cmd_vel

                                                                    │
                                                                    ▼ MAVLink

```

### 为什么飞控适配层要用 MAVLink 而不是 uXRCE-DDS

实测结论（2026-11）：uXRCE-DDS 这条路在这套硬件上是**物理层撑不住**的。

| 项 | uXRCE-DDS | MAVLink |
|---|---|---|
| 飞控固定上行流量 | **≈35 KB/s**（27 条话题里 8 条不限速全速发） | **≈4.2 KB/s**（按需轮询） |
| 115200 下的实际效果 | attitude 1.2 Hz、local_position 0.79 Hz | **local_position 稳定 24.6 Hz** |
| 460800 下 | 建立会话但 0 数据 | 不需要 |
| 能否控制发哪些 | ❌ 固件写死 | ✅ 逐条 `REQUEST_MESSAGE` 点名 |

⇒ **改用 MAVLink + 按需轮询**。代价是没有 ROS 2 QoS、需要自己处理时间同步，
但这些都在我们的控制之内，比「链路随机丢一半字节」好得多。

### 坐标系（错误 = 炸机第一名）

| 量 | 换算 |
|---|---|
| 位置 | `(x,y,z)_ENU → (y, x, −z)_NED` |
| 姿态 | `q_NED←FRD = NED_ENU_Q ⊗ q_ENU←FLU ⊗ AIRCRAFT_BASELINK_Q`（两次显式四元数乘法，**不用闭式**） |
| 机体速度 | `(vx,vy,vz)_FLU → (vx, −vy, −vz)_FRD` |
| 偏航 | `yaw_NED = π/2 − yaw_ENU`（**反射，不是常数偏移**） |

现成实现：`src/flight/px4_offboard/src/frame_transforms.cpp` + `tools/verify_frames.py`。

## 七、分工

| 谁 | 负责 |
|---|---|
| **队友（K230）** | 红点检测、视觉导航（航线→火源上方那一段）、状态机标志位输出 |

### 我们这条线的最小可交付顺序

1. **MAVLink 飞控适配**（`px4_offboard`）—— 没有它飞机不听派的话
2. **航线 + 状态机**（`competition_g`）—— 22 分的基本盘
3. **car_link**（TCP 1 Hz 坐标）—— 8 + 8 分
4. **k230_bridge**（接视觉结论）—— 发挥①②
5. 投放机构（硬件 + 一个 GPIO 节点）
