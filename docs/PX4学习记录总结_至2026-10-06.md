## 2. 已讲通的核心概念（原义版）

### 2.1 推杆后 0.01 秒的流水线（整体架构）

遥控器 SBUS → `rc_input`（收原始通道值）→ `rc_update`（用参数 `RC1_MIN/TRIM/MAX` 当翻译词典，换算成 -1~1）→ `manual_control_setpoint` topic → `commander`（状态机：模式/解锁/failsafe）→ 位置/姿态控制器 → 混控 → PWM/DShot 输出。后台并行：`EKF2` 融合 IMU/气压/光流/GPS 产出状态估计供控制器使用。**每个环节只认 topic 不认硬件**——换装备不改流水线。

### 2.2 uORB（原义）

进程内共享内存里的**结构体 + 发布/订阅 + 时间戳**。模块把结构体写进一块命名内存（topic），谁需要谁订阅读走；时间戳让读者知道数据新旧。不是"信封/邮局"，就是一张张带时间戳的公共告示板。

### 2.3 MAVLink 与地面站的分工

MAVLink = 飞控与外界通信的信封协议（命令、遥测、参数读写）。**QGC 只是录入/显示工具**：校准数据、参数真正写在**飞控参数区**（如 `RC1_MIN/TRIM/MAX`），由 `rc_update` 读取。别把工具当数据作者。

### 2.4 MANUAL_CONTROL = 虚拟遥控器

`manual_control_send(target, x滚, y俯, z油, r偏, buttons)`：x/y/r 范围 -1000~1000 中位 0；**z（油门）0~1000 中位 500**，对应真机油门通道 PWM 1000~2000 µs（中位 1500）。
**Position 模式下油门 ≠ 电机功率，而是垂直速度指令**：500 = 定高（0 m/s），>500 爬升，<500 下降；满杆 = `MPC_Z_VEL_MAX_UP`（默认 3 m/s），再叠摇杆指数 `MPC_Z_MAN_EXPO`，所以脚本用 850（实测约 1 m/s，平稳）。

### 2.5 模式/状态解码表（HEARTBEAT 字段）

| base_mode | 含义            | custom_mode | 含义                         |
| --------- | --------------- | ----------- | ---------------------------- |
| 29        | 已解锁前 Manual | 0x00030000  | POSCTL（Position）           |
| 81        | 未解锁 POSCTL   | 0x02040000  | AUTO/TAKEOFF                 |
| 157       | 已解锁（手动）  | 0x03040000  | AUTO/LOITER（Hold failsafe） |
| 209       | 已解锁 POSCTL   | 0x05040000  | AUTO/RTL                     |
|           |                 | 0x06040000  | AUTO/LAND                    |

### 2.6 PX4 1.17 关键行为（全部实测踩过）

1. `MAV_CMD_NAV_TAKEOFF` **不自动解锁**：只切模式不解锁，必须另发 `COMMAND_LONG 400 param1=1`。
2. POSCTL 解锁前提 = **手动控制信号活着**：无摇杆直接解锁报 "Arming denied: Resolve system health failures"；先喂 2 s 中位摇杆再解锁。
3. 解锁后 ~10 s 无起飞动作 → "Disarmed by auto preflight disarming"（爬太慢会在半空被没收）。
4. 空中 disarm 被拒："Disarming denied: not landed"；落地后接受，或 PX4 自动 "Disarmed by landing"。
5. 摇杆断流 → "Failsafe activated: entering Hold for 5 seconds" → RTL → 落地自动解锁。
6. **offboard 硬规矩**（电赛要用）：setpoint ≥2 Hz（实写 50 Hz）；断流 >0.5 s 自动退出 offboard 进 failsafe；遥控可抢占（`COM_RC_OVERRIDE`）。

### 2.7 MAVLink UDP 伙伴锁（SITL 端口地图）

每个 mavlink 实例**永久锁定第一个给它发数据的地址**，ACK/遥测只回给锁定方；命令任何地址来都执行。每跑一次脚本就占死一个实例，需重启 SITL 或换端口。
每次启动固定：18570 Normal（QGC 占）、14580/14280 Onboard、13030 Gimbal（忽略非 gimbal 命令）、**19450 Custom（摇杆验证可用）**。

### 2.8 三层编程模型 与 电赛架构

| 层              | 代码在哪 | 工具                                                                    | 适用                                                       |
| --------------- | -------- | ----------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1 操作层        | QGC      | Plan View 画航点                                                        | 固定航线（**室内无 GPS 时 Mission 不可用**：航点是经纬度） |
| 2 机外 offboard | 伴飞电脑 | pymavlink / MAVSDK / **ROS 2 + uXRCE-DDS + px4_msgs**                   | 动态任务、视觉/雷达驱动（电赛主战场）                      |
| 3 固件层        | 飞控内   | 自写 uORB 模块（C++），WSL `make micoair_h743-v2_default` → QGC 烧 .px4 | 无伴飞、低延迟、新驱动；**没有 Keil 例程这回事**           |

电赛架构（= 用户凌霄经验的 PX4 版）：树莓派跑 ROS 2 节点图（SLAM/视觉/任务状态机/外环 PID）→ micro XRCE-DDS Agent → 飞控 uXRCE-DDS client；uORB topic 直接映射成 ROS 2 topic（`/fmu/in/trajectory_setpoint`、`/fmu/out/vehicle_local_position` 等）。
室内定位两路线：A 融合式（SLAM 位姿→`VehicleOdometry`→EKF2 与光流融合，飞控自定点）；B 纯 offboard（派闭环 50 Hz 发 setpoint）。"光流自定点+雷达 PID 矫正"介于两者之间，电赛常用 B 或 A+B。
**室内无 GPS ⇒ 飞控跑不了存好的航点程序；航点必须由派实时喂（offboard）**。

## 3. 已验证飞行配方（flight14.py，7 次成功）

POSCTL（`DO_SET_MODE 176 p1=1 p2=3`）→ 中位摇杆 20 Hz × 2 s → 解锁（400, p1=1）→ z=850 爬升（vz≈-1 m/s，"Takeoff detected"）→ z=500 悬停 → z=200 下降 → 落地后 disarm（400, p1=0）。
遥测用 `SET_MESSAGE_INTERVAL`（COMMAND_LONG 511）开 GLOBAL_POSITION_INT / LOCAL_POSITION_NED @2 Hz。注意 rel 高度偶有 ±1 m 单帧跳变，判断条件别信单帧。
