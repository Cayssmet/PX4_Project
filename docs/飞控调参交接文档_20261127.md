# 飞控调参交接文档（2026-11-27）

> **这份文档是给"专门负责把飞机调稳"的对话用的。** 它之前的上下文为零，所以从硬件到参数到每一次炸机的原因都写全了。
>
> 项目背景：2023 全国电赛 G 题《空地协同智能消防》。飞机要在室内 4.8 m × 4.0 m 场地里、18 dm 高度按蛇形航线全覆盖巡逻，用雷达建图定位（无 GPS），靠光流 + 测距维持位置与高度，最终用 PX4 offboard 模式由树莓派发设定点全自动飞。
>
> **当前阶段**：软件链路（树莓派 ↔ 飞控 MAVLink）已打通，飞机能稳定悬停但**航向估计不稳**、**姿态手感偏软**。电调/电机/结构都已经上过电试飞过多次，炸过 1 次。

---

## 0. 一句话现状

飞机现在能做到：Stabilized 手动起飞 → 悬停 → 切 Position 定点（52 秒漂 0.35 m）→ 自动落地检测上锁。**没做到的**：航向估计始终不稳（每份日志结尾都有 `Preflight Fail: heading estimate not stable`）、姿态响应偏软、罗盘新息长期超标。

**调参的第一优先级应该是航向/罗盘，不是姿态增益。**

## 3. 已经查清的四个"看起来像故障、其实是设计"的现象

### 3.1 起飞必须推到 65% 油门、且没有电机怠速

**源码（PX4 硬编码，参数改不了）**

```cpp
// src/modules/flight_mode_manager/tasks/ManualAltitude/FlightTaskManualAltitude.cpp:325
bool FlightTaskManualAltitude::_checkTakeoff()
{
    // stick is deflected above 65% throttle (throttle stick is in the range [-1,1])
    return _sticks.getPosition()(2) < -0.3f;   // 注意符号相反 ⇒ 实际 = throttle > +0.30
}
```

- 未过门槛时，`MulticopterPositionControl.cpp:487-494` 会把整个设定点替换成「向下 100 m/s²，确保没有推力」（注释原文 `make sure there's no thrust`），`resetIntegral()`。
- 1.14.4/1.17 全树**没有 `MOT_SPIN_ARM` / `MOT_SPIN_MIN`**，所以"怠速"这个概念在这版固件里不存在。
- **起飞要 62.5% 而不是 65%** 的原因：`RC3_MIN=1027`（不是 1000），中点是 1515，门槛落在 `1515+0.3×488 ≈ 1661 µs`。

**正确起飞手法**：油门推到约 70% → **看到起转立刻回中（1515 µs）** → `MPC_TKO_RAMP_T` 会自己把推力升到 `MPC_THR_HOVER`。那 70% 只是"我要起飞"的触发信号，不是要 70% 推力。

### 3.2 「解锁了推油门电机不转」

就是 3.1 那条：`want_takeoff` 没触发 ⇒ `minimum_thrust = 0`。**不是坏件、不是安全开关、不是光流问题。**

三份日志（log_72/73/log_0~2）里油门最大只到 0.184（59%），全部卡在门槛之下。

### 3.3 QGC 的 Actuators 滑块测电机会"抽动"

`src/lib/mixer_module/actuator_test.cpp`：`:53-56` 超过 100 ms 的旧指令直接丢弃；`:71-73` 记录 `timeout_ms`；`:120-122` 超时退出测试模式、输出回停转值。QGC 在 Windows 上会卡顿 ⇒ 指令间隔一超 100 ms 电机就停一下。

**结论：滑块只能粗看方向，不能判断电机健康。** 健康判断用遥控器 Stabilized 推到 20–30% 听/看（实测无抽动、四路接近同步）。

### 3.4 自定义帧里 `dist_bottom_valid` 常年 False

`EKF2.cpp:1470-1472`
```cpp
lpos.dist_bottom = math::max(_ekf.getTerrainVertPos() - lpos.z, 0.f);
lpos.dist_bottom_valid = _ekf.isTerrainEstimateValid();
```
`dist_bottom` 来自**地形估计器**，不是测距直读。地形估计有效只影响地形跟随与精确降落，定高悬停用不到。**高度融合本身是好的**（`cs_rng_hgt` 全程 100% true）。

## 4. 每一次事故的原因（★ 别重复推理）

### 4.1 log_2 侧翻炸机（Position 模式，唯一一次真炸）

**结论：不是参数符号问题，是「推力不足以干脆离地 → 停在离地临界点 → 地面接触 + 机架松动产生大扰动 → 姿态环差分饱和 → 总推力被吃掉 → 更离不了地 → 翻转」。**

| 证据 | 数据 |
|---|---|
| **从未离地** | 测距 1.0 s 时 0.210 m → 4.5 s 时 0.220 m，**只抬高 1 厘米** |
| **控制器要 94.6% 推力，实际只有 49%** | 5.4 s 推力设定点 −0.946，但四路 `(0.874+0.010+1.000+0.076)/4 = 0.49` ⇒ **差分饱和把总推力吃掉了**（M3 顶 1.000、M2 掉 0.010） |
| **角速率远超控制器许可** | 峰值 pitch **1298 °/s**，而 `MC_ROLLRATE_MAX = 100` ⇒ 只可能来自物理侧 |
| 事件序列 | 5.76 s `Disarming denied: not landed` → 6.11 s `Preflight Fail: Attitude failure (roll)` → 7.89 s `Failsafe activated` → 9.74 s `invalid setpoints` + `Failsafe: blind land` |
| 事后发现 | 炸机后**机体固定的铜柱直接滑出**，机体当时不牢固 |

**教训**：起飞阶段推力必须"果断"，不能停在离地临界点磨；机体结构刚度是安全项。

### 4.2 「一直往后飘、加油门就往上冲」——水平基准是假值

- 当时 `SENS_BOARD_Y_OFF = +2.4514°` ⇒ 自稳目标被偏了 2.45°，飞机必须物理仰头 PX4 才认为"水平" ⇒ 推力后倾 ⇒ 持续后飘。定量：9.81 × sin(2.4514°) = **0.42 m/s²**，与实测 0.27–0.35 m/s² 同量级同方向。
- **为什么会累积成假值**：`src/modules/commander/level_calibration.cpp:123` 是「旧偏移 + 残差」的累加，`:146-151` 有 **0.8° 硬门槛**：

```cpp
} else if (fabsf(roll_mean) > 0.8f) {
    calibration_log_critical(mavlink_log_pub, "excess roll angle");
} else if (fabsf(pitch_mean) > 0.8f) {
    calibration_log_critical(mavlink_log_pub, "excess pitch angle");
} else {
    ... param_set_no_notification(...);   // :165-166 只有成功才写
```

⇒ 偏移已经 2.45° 时再做校准必然 >0.8° ⇒ **永远失败、值永远不变 = 死锁**。

- **正确修复顺序**（已执行，现在偏置 0.35°/0.24°，静置 roll 0.21–0.25°、pitch 0.13–0.17°）：
  1. `SENS_BOARD_X_OFF = 0`、`SENS_BOARD_Y_OFF = 0`
  2. **重启飞控**（参数只在 `src/lib/sensor_calibration/Accelerometer.cpp:142` / `Gyroscope.cpp:129` / `Magnetometer.cpp:127` 的**构造函数**里读一次，不重启等于没改）
  3. 读 `listener vehicle_attitude -n 1` 得到台面真实倾斜
  4. 若 |roll| 或 |pitch| > 0.8° 就**用纸片垫机脚**，垫到两个都 <0.8°
  5. 做 Level Horizon，**看 QGC 消息栏有没有 `level calibration done`**（不看数字）
  6. 再重启一次
  7. 再读 `vehicle_attitude`，应 <0.5°

### 4.3 `MPC_THR_HOVER` 填低导致的"切模式掉高度 / 起飞后先沉"

早期是 0.5，实测悬停需要 **0.579–0.592**。已改 0.58。

### 4.4 Position 下"缓慢向上飞" —— 是油门杆的锅

- `corr(throttle, vz) = −0.750`、`corr(throttle, 爬升率) = +0.737`；油门 0.10–0.13 时平均 1.6 cm/s、0.18–0.25 时 5.3 cm/s。
- **真正的油门零点在 1515.5 µs**，而遥控器物理中位实测停在 **1559–1573 µs**（高 44–58 µs ⇒ +0.09~+0.12 的爬升指令）。遥控器是**带棘齿、不自动回中**的飞机式油门。
- Position/Altitude 模式的杆→爬升率是**平方映射**：`expo(x) ≈ x²`，`x=1` 时等于 `MPC_Z_VEL_MAX_UP`。所以 `Z_VEL_MAX_UP=2.0` 时杆到 70% 就是 0.96 m/s，非常猛——这也是"Position 起飞太猛"的量化原因。

**建议动作**：重做罗盘校准（远离电源线、电调、金属台面），必要时把磁力计架高或换外置；确认 `CAL_MAG0_ROT` 与实际安装一致；校完重启再看 `cs_mag_hdg` 与 `hdg_test_ratio`。

> 注意 `unaided_heading` 与 `heading` 曾差约 180°（log_15），无 GPS 时该字段本身不可靠，不要单独用它判断。

### ★★ P2 姿态响应偏软（"不跟手"）

`MC_ROLL_P=MC_PITCH_P=4.3`、`MC_ROLLRATE_MAX=MC_PITCHRATE_MAX=120`、`MC_YAWRATE_MAX=100`，都远低于默认。
定量：`角度环 P × 角度误差 = 角速率需求`，P=4.0 时 **25° 误差就要 100 °/s**，正好撞上限；40° 误差要 160 °/s 却被削到 100。

**已验证有效的测试法**（30 秒）：Position 悬停 0.5 m → 横滚杆推 50% 保持 0.5 s 回中 → 看倾斜到位时间与回正是否摆动 → 俯仰再做一次 → 落地看日志。
- 倾斜 >0.5 s 才到最大角 ⇒ `MC_ROLL_P` 继续加
- 回中后来回摆 1–2 次 ⇒ 加太快了，退回上一档
- 倾斜快、回正干脆、不摆 ⇒ 这组对了

### ★★ P3 加速度计振动（124–129 Hz）

`sensor_gyro_fft` 主峰：X 123.4 / 124.5 / 127.2 Hz，Y 128.3–129.4 Hz，Z ~49.6–50.9 与 ~123.7–124.7 Hz。
`accel_vibration_metric`：地面 0.03–0.33，**电机一转就 4.9–9.6 m/s²**（PX4 实践目标 <3）；`accel_clipping[2]` 曾到 1.0。
`gyro_vibration_metric` 只有 0.007–0.24、`gyro_clipping` 全 0 ⇒ **减震还在起作用，别盲目换更软的垫**。

★ **坑**：`IMU_GYRO_FFT_SNR` 默认 10，而实测峰 SNR 只有 4.3–8 ⇒ **PX4 的自动 FFT 识别不到这个峰**，必须手填陷波器。

### ★ P4 位置环偏慢

`MPC_XY_VEL_P_ACC = 2.2` ⇒ 时间常数 0.45 s、到 90% 约 1.0 s，与实测（Position 下杆→速度滞后 **+1.00 s，r = 0.802**）吻合。可加到 2.6，**但必须等 P2 稳定后再动**。

### P5 其它待确认

- `MPC_USE_HTE=1` 但 `hover_thrust_estimate` 整段 NaN ⇒ 估计器没出值。
- `EKF2_EV_DELAY=0`：树莓派送视觉位姿后需要按实测延迟调（起手 30 ms）。
- 雷达相对重心的外参（`EKF2_EV_POS_X/Y/Z`）需实测。
- 机体轴距、桨叶型号、电机 KV 未知（赛题限制轴距 ≤45 cm、桨叶必须全防护）。

## 6. 建议的调参顺序（一次只改一组）

| 步骤 | 改什么 | 判据 |
|---|---|---|
| 1 | **罗盘重做** + 确认 `cs_mag_hdg` 变 true | `hdg_test_ratio` 稳定 <1.0；日志不再出现 heading not stable |
| 2 | `MPC_THR_HOVER` 复核（现 0.58） | Stabilized 悬停半米、手不碰油门，高度基本不动 |
| 3 | `MC_ROLL_P`/`MC_PITCH_P` 4.3 → **5.5** → 观察 → **6.5** | §5-P2 的 30 秒测试法 |
| 4 | `MC_ROLLRATE_MAX`/`MC_PITCHRATE_MAX` 120 → **150** → **180**；`MC_YAWRATE_MAX` 100 → 150 | 同上，出现 1–2 Hz 往复摆动就退 |
| 5 | 振动：`IMU_GYRO_NF0_FRQ=125`、`IMU_GYRO_NF0_BW=20`、`IMU_GYRO_NF1_FRQ=50`、`IMU_GYRO_CUTOFF` 80→70 | `accel_vibration_metric` 明显下降；`IMU_GYRO_DNF_EN` 先别开 |
| 6 | `MPC_XY_VEL_P_ACC` 2.2 → **2.6** | 杆→速度滞后下降且不振荡 |

**铁律**：一次只改一组；改完重启飞控（有一半参数只在启动时读）；每次飞完留 `.ulg`。

## 7. ★ 绝对不能动的东西（动了就别的地方会坏）

1. **`MAV_1_CONFIG = 102` 与 `SER_TEL2_BAUD = 115200`** —— MTF-01 光流的生命线。早前文档里有一条"把 `MAV_1_CONFIG` 置 0 腾出 TELEM2 给树莓派"的必改项，**那是作废的**，照做光流立刻消失。
2. **`MAV_2_CONFIG = 103`、`MAV_2_MODE = 7 (Minimal)`、`SER_TEL3_BAUD = 115200`** —— 树莓派链路。不要把它改回 TELEM4（那是板载蓝牙）。
3. **`EKF2_EV_CTRL = 1`、`EKF2_HGT_REF = 2`、`EKF2_OF_CTRL = 1`、`EKF2_RNG_CTRL = 1`** —— 位置/高度来源，都有实测证据支撑。
4. **`CA_ROTOR*`** 已用 Motor Test 逐路核对，不要再改。
5. **`SENS_BOARD_*_OFF` 改完必须重启**，不然不生效（看起来像"校准没用"）。
6. **不要用 QGC 的 Actuators 滑块判断电机健康**（见 §3.3）。
7. 改 `MPC_Z_VEL_MAX_*` 之后，回头检查 `MPC_TKO_SPEED` 与 `MPC_LAND_SPEED` 有没有被自动夹小。

### 8.2 两个必须知道的读取坑

- **PX4 把 INT32 参数的位模式当 float 发**：`PARAM_VALUE.value(f32)@0`，要按 `param_type` 还原（`struct.unpack('<i', struct.pack('<f', v))[0]`）。否则 `SYS_AUTOSTART` 读成 0。
- **MAVLink v2 帧头是 10 字节**（签名再 +13）。按 12 算会让整个载荷错位 2 字节，所有值读错。

### 8.3 日志

**分析用 `pyulog`**（已装在 `tools/.pylibs`）：
```python
from pyulog import ULog

u.initial_parameters          # dict，含全部参数快照

```
字段名坑：`vehicle_attitude_setpoint` 用 `q_d[0..3]` + `thrust_body[2]`；`vehicle_land_detected` 用 `landed`；`estimator_status` 在 PX4 1.17 里是 `hdg_test_ratio`（1.14 是 `mag_test_ratio`）；`actuator_motors` 是 `control[0..11]`。

**注意 tlog 不可靠**：这台机器上多个 tlog 的 `LastWriteTime` 早于 `CreationTime`（系统时钟被回拨过），不能拿它判断"有没有连上"。判"QGC 真连上了"看 `%APPDATA%\QGroundControl\ParamCache\1_1.v2` 有没有刷新。

## 10. 给接手的人的三句话

1. **先修航向，再调手感。** 现在每份日志都在报 heading not stable，`hdg_test_ratio` 顶格，这不是"增益没调好"能盖住的。

3. **起飞要果断**：油门推过门槛就立刻回中，别停在离地临界点磨。log_2 那次就是磨出来的。
