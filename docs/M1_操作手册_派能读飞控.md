# M1 操作手册 · 让树莓派读到飞控

> 配套：`PX4伴飞工程计划书.md` §11.1（参数）、§5.1（DDS 白名单）、§12（派侧清单）。
> 本关**不需要电机 / 电调 / 桨**，只要飞控 + 一根 CH340 USB-TTL + 树莓派。
> 全程预计 40~70 分钟，其中 Agent 编译占大头。

---

## 0. 这一关要拿到什么

**目标**：树莓派上 `ros2 topic list` 能看到 `/fmu/out/*`，也就是**派能读飞控**。

**判据（三条全过才算过）**

| # | 命令 | 期望 |
| --- | --- | --- |
| 1 | `ros2 topic list \| grep fmu` | 出现一批 `/fmu/in/...` 和 `/fmu/out/...` |
| 2 | `ros2 topic hz /fmu/out/vehicle_status` | 约 **5 Hz**（不是 0，不是几百 Hz） |
| 3 | 拨 CH5 模式开关，`ros2 topic echo /fmu/out/vehicle_status --field nav_state` | 数值跟着变 |

**通过后不要急着往下**——先把「§9 可选：做成开机自启」留着，等 M2 也通过再固化。

## 2. 接线（★ 有个物理坑）

```
飞控 TELEM2  ──┬── TX  ──────────►  CH340 RX
（UART4）      ├── RX  ◄──────────  CH340 TX
               └── GND ───────────  CH340 GND
CH340 ──── 树莓派 USB 口
```

**四条纪律**

1. **TX/RX 必须交叉**（飞控的 TX 进 CH340 的 RX）。接反了完全不通信，且不报错。
2. **GND 必须连**。不共地 = 随机垃圾数据。
3. **★ 必须插回原来那一个 USB 口。** 你现有的 udev 规则 `/etc/udev/rules.d/99-uav-flight-controller.rules` 用的是**物理路径**匹配：
   ```
   ENV{ID_PATH}=="platform-xhci-hcd.1-usb-0:1:1.0"
   ```
   规则注释原文：*"The CH340 has no unique serial number, so the physical path is required."*
   ⇒ 换一个 USB 口，`/dev/flight_controller` 就**不会出现**。
   （实在要换口：先用 `/dev/ttyUSB0` 代替，并把 Agent 的 `--dev` 一起改掉。）
4. **不要从飞控的 5V BEC 给树莓派供电**（MicoAir H743 v2 手册：5V BEC 上限 **3 A**，带不动派 5）。派用自己的电源。

**接好后在派上确认**：

```bash
ls -l /dev/flight_controller
# 期望：lrwxrwxrwx ... /dev/flight_controller -> ttyUSB0

ls -l /dev/ttyUSB*
# 期望：crw-rw---- 1 root dialout ... /dev/ttyUSB0

groups | tr ' ' '\n' | grep -x dialout
# 期望：dialout        （没有的话 curl 不出来：sudo usermod -aG dialout $USER 然后重新登录）
```

看不到设备时看内核日志（你的 `ljz` 在 `adm` 组，不需要 sudo）：

```bash
journalctl -k -b --since "5 min ago" | tail -30
```
期望能看 `ch341` / `usbserial` 之类的行。**注意 `dmesg` 需要 sudo，BatchMode ssh 下用不了，用上面这条。**

## 3. 飞控侧参数（QGC → 参数）

> 逐字依据：`src/modules/uxrce_dds_client/module.yaml` @ v1.17.0、官方 `docs/en/middleware/uxrce_dds.md` @ v1.17.0。

| 参数 | 设为 | 为什么 |
| --- | --- | --- |
| `MAV_1_CONFIG` | **0（Disabled）** | ★ 官方默认 **MAV_1 = TELEM2** 用来给伴飞电脑发 MAVLink。**不禁掉就会和 XRCE 抢同一个串口。** 官方原文：*"Disable by setting `MAV_0_CONFIG=0` or `MAV_1_CONFIG=0` to zero."* |
| `UXRCE_DDS_CFG` | **TELEM2** | 在 QGC 下拉框里按名字选，不用记枚举值 |
| **TELEM2 的波特率**（QGC 标签 "TELEM2 Baudrate"，参数名 `SER_TEL2_BAUD`） | **921600** | ★ **最容易漏的一项。** 模块启动行原文是 `-b p:${BAUD_PARAM}`，`${BAUD_PARAM}` 展开成所选串口的波特率**参数名** —— 选 TELEM2 就吃 `SER_TEL2_BAUD`。它默认一般只有 **57600**，和 Agent 的 `-b 921600` 不一致时**一个 topic 都收不到，而且不报错** |
| `UXRCE_DDS_SYNCT` | 1（默认，别动） | 时间戳同步 |
| `UXRCE_DDS_DOM_ID` | 0（默认） | 必须和派上的 `ROS_DOMAIN_ID` 一致 |
| `UXRCE_DDS_KEY` | 1（默认） | 只有多机共用一个 Agent 时才要唯一 |
| `UXRCE_DDS_AG_IP` / `UXRCE_DDS_PRT` | 不动 | 那两个只在**走网口**时才生效（`requires_ethernet`），我们走串口 |

**改完重启飞控**（拔插电或 QGC 里 Reboot）。

**重启后复查**：`MAV_1_CONFIG` 是否仍是 0。QGC 有时会因为界面缓存看起来没变，以实际读回的值为准。

> 提醒：这一步**不影响**你原来的飞控使用——遥控器、模式开关、手动飞照旧。XRCE 客户端只是多挂了一条链路。

## 4. 树莓派上编译安装 Micro-XRCE-DDS Agent

### ★ 版本硬约束（装错会"连上了但建不了 topic"）

PX4 1.17 的 XRCE 客户端基于 **XRCE v2.x**，**与 v3.x 的 Agent 不兼容**。

| ROS 2 版本 | Agent 版本 |
| --- | --- |
| Humble | v2.4.2 |
| **Jazzy（你的派）** | **v2.4.3** |

### 安装

```bash
sudo apt update
sudo apt install -y git cmake build-essential libssl-dev

cd ~
git clone -b v2.4.3 https://github.com/eProsima/Micro-XRCE-DDS-Agent.git
cd Micro-XRCE-DDS-Agent
mkdir build && cd build
cmake ..
make -j4                      # 树莓派 5 上约 10~30 分钟
sudo make install
sudo ldconfig /usr/local/lib/

which MicroXRCEAgent
# 期望：/usr/local/bin/MicroXRCEAgent
```

**★ 不要用 snap 版**：`sudo snap install micro-xrce-dds-agent` 的 stable 版能连上飞控，但**建不出 topic**（要 `--edge` 通道才行）。源码编译最稳。

> 编译中途报找不到 `fastcdr` / `fastdds` 是正常的——Agent 会把它们作为子依赖一起拉下来编。只要没报错就继续等。

## 5. 起 Agent（窗口 A）

```bash
MicroXRCEAgent serial --dev /dev/flight_controller -b 921600
```

期望输出里出现 `Running...` 以及会话建立的信息。

**两个易错点**
- 官方文档把设备名写成 `/dev/AMA0`，是**笔误**，正确的是 `/dev/ttyAMA0`；而我们走 CH340，所以用 `/dev/flight_controller`。
- `-b` 的值必须**和 `SER_TEL2_BAUD` 完全一致**。921600 在你的 CH340 上如果不稳，两边一起退到 **460800** 再试。

**让这个窗口一直开着**，下一步在窗口 B 里做。

---

## 6. 验证（窗口 B）

```bash
source /opt/ros/jazzy/setup.bash

ros2 topic list | grep fmu | head -40
ros2 topic hz /fmu/out/vehicle_status
ros2 topic echo /fmu/out/vehicle_status --field nav_state
```

对照 §0 的三条判据逐条打勾。

**几个必须知道的正常现象**
- **只有一部分 `fmu` topic 是正常的。** 派能看到的 `/fmu/out/*` 是 PX4 源码 `src/modules/uxrce_dds_client/dds_topics.yaml` 里的**白名单**，只有约 27 条。白名单外的话题在 DDS 里**根本不存在，不会报错**。
- `/fmu/out/vehicle_angular_velocity` **不存在**（源码里被注释掉了）。
- `vehicle_local_position` / `vehicle_global_position` 的 rate_limit 是 **50 Hz**，不是"原始频率"。
- `/fmu/in/*` 是**派发给飞控**的方向，现在没人发，所以只有话题名、没有数据。

## 7. 失败对照表

| 现象 | 最可能的原因 | 怎么确认 |
| --- | --- | --- |
| Agent 报打不开串口 | 设备名不对 / 不在 `dialout` 组 / 口插错了 | `ls -l /dev/flight_controller`；`groups` |
| Agent 起来了，但 `ros2 topic list` **一个 fmu 都没有** | ① Agent 版本是 v3.x ② `SER_TEL2_BAUD` 没改 ③ `MAV_1_CONFIG` 没置 0 抢串口 ④ 飞控那侧没重启 | 依次排除；先查 ②，它是静默失败 |
| 只有零星几个 topic，`vehicle_status` 也是 0 Hz | 波特率不匹配（半数丢帧） | 两边统一成 460800 再试 |
| `ros2 topic hz` 一直显示 0 但 topic 在 | **Clash Verge 的 TUN 网卡**（`Meta 198.18.0.1/30`）干扰 DDS 组播发现 | `ip a` 看有没有 `Meta`；临时停掉 Clash 再试。也可试 `export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` |
| 拨开关 `nav_state` 不变 | 你拨的是 CH6（解锁）不是 CH5（模式）；或看的字段名不对 | 直接 `ros2 topic echo /fmu/out/vehicle_status` 看全字段 |
| 飞控 QGC 连不上了 | 把 `MAV_0_CONFIG` 也误设成 0 了 | 只改 `MAV_1_CONFIG`，`MAV_0`（TELEM1/USB）留给 QGC |

## 8. M1 通过之后

1. **把 Agent 做成开机自启的 systemd 服务**（模板见下），免得每次 ssh 进去手敲。
2. 然后进入 **M2**（派能命令飞控，不解锁）：clone `px4_msgs` 的 `release/1.17` 分支 → `colcon build` → 发 `DO_SET_MODE` → 看 `vehicle_command_ack`。

```ini
# /etc/systemd/system/micro-xrce-agent.service
[Unit]
Description=Micro XRCE-DDS Agent (PX4 companion)
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/MicroXRCEAgent serial --dev /dev/flight_controller -b 921600
Restart=always
RestartSec=3
User=ljz
Group=dialout

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now micro-xrce-agent
systemctl status micro-xrce-agent
```

> 注意：`User=ljz` 时服务需要能打开 `/dev/flight_controller`（`dialout` 组，规则里已 `MODE="0660"`）。**不要用 root 跑**，否则以后 ROS 2 的共享内存/DDS 权限会不一致。
> 另外：你这个服务要等 M2 验证过再 `enable`，否则它会和后面手工调试的 Agent 抢串口。
