# k230_bridge —— K230 庐山派下视相机桥

## 这个包负责什么 / 不负责什么

| | |
|---|---|
| **负责** | 从串口读 K230 发来的结构化数据与状态机标志位，转成 ROS 2 话题 |
| **不负责** | 图像处理、红点识别、视觉导航算法 —— **全部在 K230 上用 CanMV 实现，由队友编写** |
| **不负责** | 灭火包投放机构控制（那是独立的 GPIO/舵机节点） |

一句话：树莓派这边**从不看画面**，只收 K230 已经算好的结论。

## 为什么这样分工

赛题要求「一键启动后全程不得人为干预」，所以视觉必须在机上闭环。
K230 是 RISC-V + KPU 的 AI 相机板，红点检测与视觉循迹在它上面跑最省事，
树莓派只做「拿到结论 -> 决定飞哪」这一层。

## 待定的接口（写代码前必须先和队友对齐）

K230 通过 UART 发给树莓派的内容，目前设想的字段：

| 字段 | 含义 | 备注 |
|---|---|---|
| `red_target_found` | 是否看到红点 | bool |
| `red_target_px` / `red_target_py` | 红点在画面中的像素坐标 | 用于视觉伺服 |
| `red_target_dx` / `red_target_dy` | 相对画面中心的偏差 | 也可由树莓派自己算 |
| `nav_cmd` | 视觉导航阶段的指令/阶段标志 | 枚举，待定 |
| `state_flags` | 状态机标志位（是否对准、是否到达上方、是否可投放） | bitmap，待定 |
| `timestamp` | K230 侧时间戳 | 用于判新鲜度 |

**这些名字与帧格式都还没定**，等和队友确认后写进本包 README 与 `uav_interfaces`。
