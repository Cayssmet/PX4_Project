# k230_bridge —— K230 庐山派下视相机桥

## 这个包负责什么 / 不负责什么

| | |
|---|---|
| **负责** | 从串口读 K230 发来的结构化数据与状态机标志位，转成 ROS 2 话题；并把高度、模式指令下发回去 |
| **不负责** | 图像处理、红点识别、视觉导航算法 —— **全部在 K230 上用 CanMV 实现，由队友编写** |
| **不负责** | 灭火包投放机构控制（那是独立的 GPIO/舵机节点） |

一句话：树莓派这边**从不看画面**，只收 K230 已经算好的结论。

## 为什么这样分工

赛题要求「一键启动后全程不得人为干预」，所以视觉必须在机上闭环。
K230 是 RISC-V + KPU 的 AI 相机板，红点检测与视觉循迹在它上面跑最省事，
树莓派只做「拿到结论 -> 决定飞哪」这一层。

## ★ 协议已定稿：见 `docs/通信协议设计_v1.md`

帧格式、字段、CRC 向量都在那份文档里，**并且有可执行的参考实现**：

```bash
python3 tools/proto_selftest.py        # 33 项自检，全部通过才算协议实现对了
```

本包要收发的帧（链路 A）：

| 方向 | TYPE | 名称 | 频率 |
|---|---|---|---|
| Pi → K230 | `0x00` | HEARTBEAT | 5 Hz |
| Pi → K230 | `0x01` | CMD_MODE（STANDBY/SEARCH/ALIGN/STOP） | 变化时 |
| Pi → K230 | **`0x03`** | **CMD_SET_HEIGHT** | **10 Hz** |
| K230 → Pi | `0x81` | VISION_STATE | 30 Hz |
| K230 → Pi | `0x82` | EVENT | 事件 |
| K230 → Pi | `0x83` | STATUS | 1 Hz |

### 为什么要下发高度

K230 把**像素**偏差换成**地面 cm** 偏差，公式是 `off_cm = (像素偏差) × 高度 / 像素焦距`。
**高度错多少，cm 就按同样的比例错多少。**

以前凌霄飞控不给高度，K230 只能用一个**固定高度**凑；现在树莓派能从飞控拿到高度
（EKF 的 `dist_bottom` 优先，退而求其次 `LOCAL_POSITION_NED.z` 取负），
所以由本包以 10 Hz 把高度推给 K230，K230 实时换算并回显它实际用了多少。

高度失效时**发 `valid=0`**，让 K230 退回固定高度，并在 `VISION_STATE.flags` 置
`HEIGHT_FIXED`(bit5) —— 此时 `k230_bridge` 应把视觉伺服的增益调小（比例错了，增益不能再大）。

## 串口参数

| 项 | 值 |
|---|---|
| 设备 | **`/dev/k230`**（USB-CH340，udev 固定）；接 GPIO 时用 `/dev/ttyAMA0` |
| 波特率 | **115200**，8N1，无流控 |
| 电平 | **TTL 3.3V**，TX/RX 交叉，**必须共地** |

★ **设备名必须是 launch 参数**（`serial_device`），因为 K230 现在接 GPIO、之后改 USB-CH340，
换线时不该改代码。

★★ **两个 CH340 会撞车**：飞控与 K230 都是 `1a86:7523` 且都没有序列号，
只能靠「插在哪个 USB 口」区分。规则模板与三条操作纪律见协议文档 §9。
